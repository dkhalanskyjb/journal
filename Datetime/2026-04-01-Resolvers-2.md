Temporal resolvers: specific APIs
=================================

Usage scenarios
---------------

### Constructing an Instant from a LocalDateTime (or adjusting: current default)

Baseline: the current API.

```kotlin
suspend fun delayUntil(time: LocalTime, getTimeZone: () -> TimeZone) {
    val ldt = Clock.System.todayAt(getTimeZone()).atTime(time)
    /////////////////////////////////////
    val instant = ldt.toInstant(getTimeZone())
    /////////////////////////////////////
    while (Clock.System.now().toLocalDateTime(getTimeZone()) < ldt) {
        val remainingTime = instant - Clock.System.now()
        delay(1.seconds)
    }
}
```

With a resolver:

```kotlin
suspend fun delayUntil(time: LocalTime, getTimeZone: () -> TimeZone) {
    val ldt = Clock.System.todayAt(getTimeZone()).atTime(time)
    /////////////////////////////////////
    val instant = ldt.toInstant(getTimeZone(), InstantResolver.Compatible)
    /////////////////////////////////////
    while (Clock.System.now().toLocalDateTime(getTimeZone()) < ldt) {
        val remainingTime = instant - Clock.System.now()
        delay(1.seconds)
    }
}
```

With an enumeration:

```kotlin
suspend fun delayUntil(time: LocalTime, getTimeZone: () -> TimeZone) {
    val ldt = Clock.System.todayAt(getTimeZone()).atTime(time)
    /////////////////////////////////////
    val instant = run {
        val offset = when (val info = getTimeZone().infoAt(ldt)) {
            is LocalDateTimeOffsetInfo.Regular -> info.offset
            is LocalDateTimeOffsetInfo.Transition -> info.offsetBefore
        }
        ldt.toInstant(offset)
    }
    /////////////////////////////////////
    while (Clock.System.now().toLocalDateTime(getTimeZone()) < ldt) {
        val remainingTime = instant - Clock.System.now()
        delay(1.seconds)
    }
}
```

### Constructing an Instant from a LocalDateTime (or failing)

If someone wants to check for gaps.

Baseline: the current API.

```kotlin
suspend fun delayUntil(time: LocalTime, getTimeZone: () -> TimeZone) {
    val ldt = Clock.System.todayAt(getTimeZone()).atTime(time)
    /////////////////////////////////////
    val instant = with(getTimeZone()) {
        val instantEstimate = ldt.toInstant()
        require(instant.toLocalDateTime() == ldt) {
            "The time $time falls into a time gap! Choose a valid one."
        }
        instantEstimate
    }
    /////////////////////////////////////
    while (Clock.System.now().toLocalDateTime(getTimeZone()) < ldt) {
        val remainingTime = instant - Clock.System.now()
        delay(1.seconds)
    }
}
```

With a resolver:

```kotlin
suspend fun delayUntil(time: LocalTime, getTimeZone: () -> TimeZone) {
    val ldt = Clock.System.todayAt(getTimeZone()).atTime(time)
    /////////////////////////////////////
    val instant = ldt.toInstant(getTimeZone(), InstantResolver.Failing)
    /////////////////////////////////////
    while (Clock.System.now().toLocalDateTime(getTimeZone()) < ldt) {
        val remainingTime = instant - Clock.System.now()
        delay(1.seconds)
    }
}
```

With an enumeration:

```kotlin
suspend fun delayUntil(time: LocalTime, getTimeZone: () -> TimeZone) {
    val ldt = Clock.System.todayAt(getTimeZone()).atTime(time)
    /////////////////////////////////////
    val instant = run {
        val offset = when (val info = getTimeZone().infoAt(ldt)) {
            is LocalDateTimeOffsetInfo.Regular -> info.offset
            is LocalDateTimeOffsetInfo.Gap ->
                throw IllegalArgumentException(
                    "The time $time falls into a time gap! Choose a valid one."
                )
            is LocalDateTimeOffsetInfo.Overlap -> info.offsetBefore
        }
        ldt.toInstant(offset)
    }
    /////////////////////////////////////
    while (Clock.System.now().toLocalDateTime(getTimeZone()) < ldt) {
        val remainingTime = instant - Clock.System.now()
        delay(1.seconds)
    }
}
```

### Finding the noon

The current API: doesn't allow this.

With a resolver:

```kotlin
fun LocalDate.atNoonIn(timeZone: TimeZone): Instant =
    atTime(12, 0).toInstant(timeZone, InstantResolver.EarliestValid)
```

With an enumeration:

```kotlin
fun LocalDate.atNoonIn(timeZone: TimeZone): Instant {
    val noonLdt = atTime(12, 0)
    return when (val info = timeZone.infoAt(noonLdt)) {
        is LocalDateTimeOffsetInfo.Regular ->
            noonLdt.toInstant(info.offset)
        is LocalDateTimeOffsetInfo.Gap ->
            info.transitionStart
        is LocalDateTimeOffsetInfo.Overlap ->
            noonLdt.toInstant(info.offsetBefore)
    }
}
```

### Performing TimeZone-aware arithmetics on an Instant

(From <https://grep.app/search?words=true&q=DateTimeUnit.DAY%2C>)

Baseline: the current API.

```kotlin
fun everyDay(
    start: Instant, end: Instant, timeZone: TimeZone
): List<Instant> = buildList {
    var current = start
    while (current < end) {
        add(current)
        current = current.plus(1, DateTimeUnit.DAY, timeZone)
    }
}
```

With a resolver:

```kotlin
fun everyDay(
    start: Instant, end: Instant, timeZone: TimeZone
): List<Instant> = buildList {
    var current = start
    while (current < end) {
        add(current)
        current = current.plus(
            1, DateTimeUnit.DAY, timeZone,
            InstantResolver.Compatible
        )
    }
}
```

An enumeration-based API is not viable without a `ZonedDateTime`.

`ZonedDateTime`-based, with a resolver:

```kotlin
fun everyDay(
    start: Instant, end: Instant, timeZone: TimeZone
): List<Instant> = buildList {
    var current = start.atZone(timeZone)
    while (current < end) {
        add(current.resolved(InstantResolver.Compatible).toInstant())
        current = current.plus(1, DateTimeUnit.DAY)
    }
}
```

`ZonedDateTime`-based, with an enumeration:

```kotlin
fun everyDay(
    start: Instant, end: Instant, timeZone: TimeZone
): List<Instant> = buildList {
    var current = start.atZone(timeZone)
    while (current < end) {
        val offset = when (val info = current.info()) {
            is LocalDateTimeOffsetInfo.Regular -> info.offset
            is LocalDateTimeOffsetInfo.Transition -> info.offsetBefore
        }
        add(current.rawLocalDateTime.toInstant(offset))
        current = current.plus(1, DateTimeUnit.DAY)
    }
}
```

### Presenting the user with a choice on transitions

The current API does not allow this.

Only possible with an enumeration.

```kotlin
fun setAlarmForNextDay(
    time: LocalTime, timeZone: TimeZone, useEarlier: Bool?
): AlarmAction {
    val ldt = Clock.System.todayAt(timeZone)
        .plus(1, DateTimeUnit.DAY).atTime(time)
    when (val info = timeZone.infoAt(ldt)) {
        is LocalDateTimeOffsetInfo.Regular ->
            AlarmAction.SetAlarm(ldt, ldt.toInstant(info.offset))
        is LocalDateTimeOffsetInfo.Gap ->
            AlarmAction.RequireChange(
                gapStartTime =
                    info.transitionStart.toLocalDateTime(info.offsetBefore).time,
                gapEndTime =
                    info.transitionStart.toLocalDateTime(info.offsetAfter).time,
            )
        is LocalDateTimeOffsetInfo.Overlap ->
            if (useEarlier != null) {
                val offset = if (useEarlier) info.offsetBefore
                    else info.offsetAfter
                AlarmAction.SetAlarm(ldt, ldt.toInstant(offset))
            } else {
                AlarmAction.RequireDisambiguation(
                    overlapStartTime =
                        info.transitionStart.toLocalDateTime(info.offsetAfter).time,
                    overlapEndTime =
                        info.transitionStart.toLocalDateTime(info.offsetBefore).time,
                )
            }
    }
}
```

### Potentially relevant APIs

In C++:
> The offset information includes (<https://www.en.cppreference.com/w/cpp/chrono/sys_info.html>):
> * The times the given UTC offset comes into and from effect.
> * The UTC offset.
> * The deviation from the standard time (usually, 1 hour during DST, 0 otherwise).
> * The string abbreviation (like `CEST`).

This covers some other use cases we don't fulfill currently:

* Iteration over transitions in given `LocalDateTime` or `Instant` ranges:
  <https://github.com/Kotlin/kotlinx-datetime/issues/461>.
  Could be
  `TimeZone.nextTransitionAfter(Instant): LocalDateTimeOffsetInfo.Irregular`
  or
  `TimeZone.transitionsAfter(Instant): Sequence<LocalDateTimeOffsetInfo.Irregular>`
  instead.
* Obtaining the standard offset:
  <https://github.com/Kotlin/kotlinx-datetime/issues/557>.
  Could be `TimeZone.standardOffsetAt(Instant)` instead.
